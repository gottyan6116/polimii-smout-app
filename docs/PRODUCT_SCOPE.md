# PRODUCT_SCOPE — デモの実装範囲と本番化の条件

## 1. デモで実装済みの機能

| 区分 | 機能 | 備考 |
|---|---|---|
| 共通 | 自治体・年度の切替（全画面で共有・保存） | localStorage |
| 共通 | 「デモ用の架空データ」「ルールベース（生成AI不使用）」の常時表示 | 全画面上部 |
| 共通 | 出典・提供状況（公開確認済み／未確認／自治体保有）の表示 | 各パネル |
| ホーム | 2つの主要フロー、直近の文書、利用可能なデータ、ショートカット | |
| 施策評価 | KPIの目標・実績・達成率・判定（達成／未達成／判断不能）、定義と件数/人数の区別 | 年度途中は判断不能 |
| 施策評価 | SMOUT活動実績の月次推移（前年度同月比較）、表での確認 | SMOUT未利用は「データなし」 |
| 施策評価 | 施策別の成果比較（目標・実績・転換率・返信率・前年度同期間比） | |
| 施策評価 | 分析コメント（事実／仮説／推奨／要検証） | |
| 関心分析 | 年代・移住検討段階・関心テーマ・年代×テーマ・地域比較 | データ範囲・地域・年代フィルター |
| 課題分析 | 課題の4分類表示、改善施策候補、優先度（効果×難易度）、採用→計画へ反映 | |
| 施策立案 | 分析根拠と計画案の2カラム、施策の選択・編集、四半期スケジュール、KPI案と根拠 | 編集内容は自動保存 |
| 文書 | 5種テンプレート、下書き生成、本文編集、節の追加・削除、分析結果の挿入 | |
| 文書 | 保存・再編集、文書一覧、削除（確認つき） | |
| 文書 | 数値の照合（引用値が本文に残っているか）、【要確認】の検出、最終確認チェックリスト | |
| 文書 | Word（.docx）出力、印刷用スタイルによるPDF保存、プレビュー | |
| 設計 | データ取得層・分析・文書生成・生成エンジンの分離 | 実データ・LLM連携に備えた抽象化 |

## 2. 実データ連携後に実装すべき機能

- データ取り込み：カヤックからの定期データ受領（バッチ）またはAPI/MCP経由の取得、取り込み時の検証（欠損・重複・定義変更）
- 掲載プロジェクトのマスタ同期（施策との対応付けを職員が設定できるUI）
- 閲覧数などを使った転換率の精緻化、掲載本数あたりの指標
- 少数セルの秘匿表示
- データ更新履歴と、文書作成時点のデータ版の記録
- LLMによる文章生成（サーバー側）：分析層の数値のみを渡し、生成文の数値を照合する
- 文書のサーバー保存、版管理、庁内での共有・コメント
- PowerPoint 出力（説明資料）

## 3. 未確認事項

- SMOUTからPolimillへのデータ提供の可否・方式・粒度・費用（docs/DATA_REQUIREMENTS.md）
- 年代×関心テーマのクロス集計、自治体横断の参考集計の提供可否
- SMOUT未利用自治体への参考集計の提示可否
- 「返信あり率」等の正式な定義
- 共同サービスとしての名称・ロゴ・表記（現在は「SMOUTデータ活用構想」「共同サービス検討用デモ（非公式）」と表記し、正式ロゴは使用していない）
- 費用負担・収益分配・独占性などの事業条件

## 4. 本番化に必要な条件

**セキュリティ・データ保護**
- 自治体ごとのテナント分離（データ・文書）
- 認証・認可（自治体職員・管理者のロール、Qommons ONE のアカウント連携）
- データ利用許諾の範囲に応じたアクセス制御
- 監査ログ（参照・出力・編集の記録）
- 国内リージョンでのデータ処理・保管、通信・保存時の暗号化
- localStorage の保存はデモ専用。本番の認証・アクセス制御・データ保護として扱わない

**品質・運用**
- 分析ルール・算出式の自治体側レビュー（KPI定義の差異への対応）
- 生成文書の品質基準（PoCで「職員の修正回数」「作成時間」を測る）
- 障害時の連絡体制、データ更新遅延時の表示
- Qommons ONE 搭載要件（セキュリティ・品質・運用・事業適合）の審査対応

**契約**
- データ提供契約（利用範囲、二次利用、保管・削除、再提供の禁止事項）
- 自治体との利用契約・個人情報の取扱い
